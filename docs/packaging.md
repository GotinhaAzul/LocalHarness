# Packaging and releases

LocalHarness ships one static binary named `lh` for Linux x86_64 and aarch64.
This guide covers the release artifacts, the installer, the package recipes in
`packaging/`, and what CI verifies before and after a tag.

## Release artifacts

Pushing a tag `vX.Y.Z` whose version matches `Cargo.toml` runs
`.github/workflows/release.yml`. The release contains:

| Asset | Contents |
|---|---|
| `lh-vX.Y.Z-x86_64-unknown-linux-musl.tar.gz` | static x86_64 binary |
| `lh-vX.Y.Z-aarch64-unknown-linux-musl.tar.gz` | static aarch64 binary |
| `SHA256SUMS` | SHA-256 of both tarballs |
| `install.sh` | installer from this repository |
| `PKGBUILD-localharness-bin`, `PKGBUILD-localharness` | AUR recipes with checksums filled in |
| `localharness.rb` | rendered Homebrew formula |

Each tarball contains the binary, completions, and the man page at its root:

```
lh
completions/lh.bash
completions/lh.zsh
completions/lh.fish
man/lh.1
LICENSE-MIT
LICENSE-APACHE
README.md
THIRD_PARTY_NOTICES.md
```

Verify a download before running it:

```sh
sha256sum -c SHA256SUMS
```

`SHA256SUMS` is integrity data, not a signature. It protects against a corrupt
download and against a tampered mirror only as far as the checksum file itself
is authentic. Release signing is not implemented yet.

## installer

`install.sh` detects the architecture, downloads the matching tarball and
`SHA256SUMS`, verifies the checksum, and installs to `~/.local/bin`. It never
uses `sudo` and never runs a package manager. Download it and read it before
running; do not pipe it into a shell:

```sh
curl -fsSLO https://github.com/GotinhaAzul/LocalHarness/releases/latest/download/install.sh
less install.sh
sh install.sh
```

| Environment | Meaning |
|---|---|
| `LH_VERSION` | Release to install; defaults to `latest` via the GitHub API |
| `LH_INSTALL_DIR` | Binary directory; defaults to `$HOME/.local/bin` |
| `LH_INSTALL_BASE_URL` | Release download root; defaults to the GitHub release URL |
| `LH_INSTALL_SOURCE_DIR` | Read artifacts from a local directory instead of downloading |
| `LH_REPO` | `owner/name` to install from; defaults to `GotinhaAzul/LocalHarness` |
| `LH_TARGET` | Force a target triple instead of detecting one |
| `LH_NO_EXTRAS` | Set to `1` to skip completions and the man page |
| `XDG_DATA_HOME` | Completion and man-page root; defaults to `~/.local/share` |

Installed extras:

| Path | Purpose |
|---|---|
| `$XDG_DATA_HOME/bash-completion/completions/lh` | bash completion |
| `$XDG_DATA_HOME/zsh/site-functions/_lh` | zsh completion |
| `$XDG_DATA_HOME/fish/vendor_completions.d/lh.fish` | fish completion |
| `$XDG_DATA_HOME/man/man1/lh.1` | man page |

A checksum mismatch stops before anything is written and names both hashes. The
installer is tested offline against a fake release directory by
`tests/installer.rs`, and against real artifacts in a clean `debian:bookworm-slim`
container by the release workflow.

## Completions and man page

Both are generated by clap so they cannot drift from the CLI:

```sh
lh completions bash > ~/.local/share/bash-completion/completions/lh
lh completions zsh > ~/.local/share/zsh/site-functions/_lh
lh completions fish > ~/.local/share/fish/vendor_completions.d/lh.fish
lh man > lh.1
```

`clap_complete` and `clap_mangen` are build dependencies of that output only;
they add no runtime behavior. Both are MIT OR Apache-2.0, matching `deny.toml`.

## Arch Linux (AUR)

Two recipes live under `packaging/aur/`:

- `localharness-bin/` installs the prebuilt static binary. It is the fast path
  and works on x86_64 and Arch Linux ARM aarch64.
- `localharness/` builds from the tagged source with the distribution Rust
  toolchain and runs `cargo test` in `check()`.

The release workflow renders each `PKGBUILD` with the tag's `pkgver` and
checksums and attaches it to the release. A maintainer still has to copy the
rendered file to the AUR and regenerate `.SRCINFO`:

```sh
makepkg --printsrcinfo > .SRCINFO
makepkg -si
lh --version
```

The local recipe has not been built by this repository's CI; the AUR publish
step is manual.

## Nix

`flake.nix` at the repository root builds the crate with `buildRustPackage`,
installs completions and `lh.1` in `postInstall`, and exposes a dev shell:

```sh
nix build
./result/bin/lh --version

nix develop          # rustc, cargo, clippy, rustfmt, cargo-audit, cargo-deny, shellcheck
nix profile install .
```

The flake tracks `nixos-unstable`. A `flake.lock` is not committed yet; the
first `nix build` writes one and it should be committed.

## Homebrew

`packaging/homebrew/localharness.rb.in` is a formula template. The release
workflow renders it with real checksums and attaches `localharness.rb`; a tap
maintainer can also do it by hand:

```sh
sh packaging/homebrew/render.sh 0.2.0 SHA256SUMS <source-sha256> > localharness.rb
```

Linux installs the prebuilt static binary. macOS is best-effort and builds from
the tagged source with Homebrew's Rust. The formula is not in a tap and
`brew install` has not been exercised.

## Docker

The image is built from `packaging/docker/Dockerfile`. Build from the
repository root:

```sh
docker build -f packaging/docker/Dockerfile -t localharness .
docker run --rm -it -v "$PWD:/workspace" localharness
```

The final stage is `gcr.io/distroless/static-debian12:nonroot`: no shell, no
package manager, and a non-root user. The binary is static musl, so it does not
need the distroless userland. Mount the workspace and, if needed, config and
data:

```sh
docker run --rm -it \
  -v "$PWD:/workspace" \
  -v "$HOME/.config/localharness:/home/nonroot/.config/localharness" \
  -v "$HOME/.local/share/localharness:/home/nonroot/.local/share/localharness" \
  --network host \
  localharness
```

`HOME` is `/home/nonroot`, so config and sessions resolve under the mounted
paths. The TUI needs a terminal (`-it`); use `--print` for one-shot headless
runs.

## What is and is not exercised

| Check | Where |
|---|---|
| Completion and man-page generation | `tests/completions.rs` |
| Installer happy path and checksum refusal | `tests/installer.rs` (offline) |
| Installer on real artifacts in a clean container | `verify-installer` in `release.yml` |
| Static x86_64 and aarch64 builds | `build` matrix in `release.yml` |
| Docker image builds, runs, and has no shell | `docker` in `release.yml` |
| Shell syntax and shellcheck | `packaging` job in `ci.yml` |
| A real tag release and GitHub upload | Not run from this branch |
| Pushing the Docker image to a registry | Not implemented; build locally |
| AUR publish and `makepkg` build | Manual, not exercised |
| Homebrew tap install | Manual, not exercised |
| `nix build` and macOS source build | Not exercised; no Nix or macOS in CI |
